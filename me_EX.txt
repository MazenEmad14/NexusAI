شرح مشروع Mini RAG App
======================

الملف ده معمول كشرح تفصيلي للمشروع فايل فايل وفولدر فولدر.
الفكرة العامة إن المشروع عبارة عن Backend باستخدام FastAPI لتطبيق RAG بسيط.

RAG اختصار لـ Retrieval-Augmented Generation.
يعني بدل ما نسأل الموديل سؤال وخلاص، بنعمل الخطوات دي:

1. نرفع ملفات فيها المعرفة أو الداتا.
2. نقسم الملفات إلى أجزاء صغيرة اسمها chunks.
3. نحول كل chunk إلى embedding vector.
4. نخزن الـ vectors في Vector Database.
5. لما المستخدم يسأل سؤال، نحول السؤال إلى vector.
6. نبحث عن أقرب chunks للسؤال.
7. نبني prompt من الـ chunks القريبة.
8. نبعت الـ prompt للموديل عشان يولد إجابة مبنية على الداتا.

فيه endpoints الخاصة بـ FastAPI. يعني API URLs التي المستخدم أو Postman يتعامل معها.

assets/

from fastapi import FastAPI

ده بينشئ تطبيق FastAPI.

sys.path.insert(0, str(Path(__file__).resolve().parent))

بيضيف فولدر src إلى Python path.
الغرض منه إن imports زي:

from routes import base, data, nlp

تشتغل حتى لو شغلت التطبيق من root folder.

main.py بيستورد:

- routes/nlp.py

startup_db_client
-----------------

الدالة دي بتشتغل عند بداية تشغيل السيرفر:

@app.on_event("startup")
async def startup_db_client():

وظيفتها:

1. قراءة الإعدادات:
   settings = get_settings()

2. فتح اتصال MongoDB:
   app.mongo_conn = AsyncIOMotorClient(settings.MONGODB_URL)
   app.db_client = app.mongo_conn[settings.MONGODB_DATABASE]

   app.mongo_conn هو الاتصال الرئيسي.
   app.db_client هو قاعدة البيانات المحددة.

3. إنشاء factory للـ LLM:
   llm_provider_factory = LLMProviderFactory(settings)

4. إنشاء factory للـ Vector DB:
   vectordb_provider_factory = VectorDBProviderFactory(settings)

5. إنشاء generation client:
   app.generation_client = llm_provider_factory.create(provider=settings.GENERATION_BACKEND)

   ده العميل المستخدم لتوليد النصوص، مثل OpenAI أو Cohere أو Groq.

6. تحديد موديل التوليد:
   app.generation_client.set_generation_model(model_id=settings.GENERATION_MODEL_ID)

7. إنشاء embedding client:
   app.embedding_client = llm_provider_factory.create(provider=settings.EMBEDDING_BACKEND)

   ممكن يكون نفس provider أو provider مختلف.
   مثال:
   - generation من Groq
   - embeddings من OpenAI أو Cohere

8. تحديد موديل embedding:
   app.embedding_client.set_embedding_model(
       model_id=settings.EMBEDDING_MODEL_ID,
       embedding_size=settings.EMBEDDING_MODEL_SIZE
   )

9. إنشاء vector DB client:
   app.vectordb_client = vectordb_provider_factory.create(provider=settings.VECTOR_DB_BACKEND)
   app.vectordb_client.connect()

10. إنشاء TemplateParser:
    app.template_parser = TemplateParser(
        language=settings.PRIMARY_LANG,
        default_language=settings.DEFAULT_LANG
    )

    ده مسؤول عن تحميل prompt templates بلغة معينة مثل en أو ar.


shutdown_db_client
------------------

الدالة دي بتشتغل عند إغلاق التطبيق:

app.mongo_conn.close()
app.vectordb_client.disconnect()

يعني تقفل اتصال MongoDB وتفصل Qdrant client.

الكلاس الرئيسي:

class Settings(BaseSettings):

ده بيحدد كل environment variables التي التطبيق محتاجها.


model_config
------------

model_config = SettingsConfigDict(
    env_file=Path(__file__).resolve().parents[1] / ".env",
    env_file_encoding="utf-8",
    extra="ignore",
)

معناه:

- ملف البيئة موجود في src/.env.
- الترميز utf-8.
- لو فيه مفاتيح زيادة في .env مش موجودة في Settings، تجاهلها.


الإعدادات الموجودة
------------------

APP_NAME:
اسم التطبيق.

APP_VERSION:
إصدار التطبيق.

FILE_ALLOWED_TYPES:
أنواع الملفات المسموح برفعها.
مثال:
text/plain
application/pdf

FILE_MAX_SIZE:
أقصى حجم للملف بالميجابايت.

FILE_DEFAULT_CHUNK_SIZE:
حجم القراءة أثناء حفظ الملف المرفوع.
ده مش نفس chunk الخاص بالـ RAG.
ده chunk للقراءة والكتابة على الديسك.

MONGODB_URL:
رابط الاتصال بـ MongoDB.

MONGODB_DATABASE:
اسم قاعدة البيانات.

GENERATION_BACKEND:
اسم provider المستخدم في توليد النص.
مثال:
OPENAI
COHERE
GROQ

EMBEDDING_BACKEND:
اسم provider المستخدم في embeddings.

OPENAI_API_KEY / COHERE_API_KEY / GROQ_API_KEY:
مفاتيح API.

GENERATION_MODEL_ID:
اسم موديل التوليد.

EMBEDDING_MODEL_ID:
اسم موديل embedding.

EMBEDDING_MODEL_SIZE:
عدد أبعاد الـ vector الناتج من embedding model.
مثلا text-embedding-3-small حجمه 1536.

INPUT_DAFAULT_MAX_CHARACTERS:
أقصى عدد حروف يتم تمريره للموديل من النص.
لاحظ إن اسم المتغير فيه typo: DAFAULT بدل DEFAULT.
لكن طالما مستخدم بنفس الاسم في الكود والـ .env، هيشتغل.

GENERATION_DAFAULT_MAX_TOKENS:
أقصى tokens في إجابة الموديل.

GENERATION_DAFAULT_TEMPERATURE:
درجة العشوائية في الإجابة.

VECTOR_DB_BACKEND:
نوع vector database.
حاليا QDRANT فقط.

VECTOR_DB_PATH:
مسار تخزين Qdrant المحلي.

VECTOR_DB_DISTANCE_METHOD:
طريقة حساب التشابه.
مثل cosine أو dot.

PRIMARY_LANG:
لغة prompts الأساسية.

DEFAULT_LANG:
اللغة الافتراضية لو اللغة المطلوبة غير موجودة.


parse_file_allowed_types
------------------------

الدالة دي:

@field_validator("FILE_ALLOWED_TYPES", mode="before")

بتحول FILE_ALLOWED_TYPES من string إلى list.

لو القيمة مثلا:

text/plain,application/pdf

هتتحول إلى:

["text/plain", "application/pdf"]

ملاحظة:
في .env.example القيمة مكتوبة كده:

FILE_ALLOWED_TYPES=["text/plain", "application/pdf"]

لكن validator الحالي بيقسم string باستخدام comma فقط.
الأفضل في .env تكون:

FILE_ALLOWED_TYPES=text/plain,application/pdf

لأن الشكل الأول ممكن ينتج عناصر فيها أقواس واقتباسات حسب طريقة قراءة pydantic.


get_settings
------------

@lru_cache
def get_settings():
    return Settings()

دي بتقرأ الإعدادات مرة واحدة وتعمل cache.
ده مفيد لأن كل controller أو route ممكن يحتاج settings، ومش عايزين نقرأ .env كل مرة.

5.2 ملف src/routes/data.py
------------------------------------------------------------

ده مسؤول عن رفع الملفات ومعالجتها.

router:

يعني endpoints هنا تبدأ بـ:

/api/v1/data


Endpoint 1:
POST /api/v1/data/upload/{project_id}

الدالة:

upload_data(request, project_id, file, app_settings)

وظيفتها رفع ملف وربطه بمشروع معين.

الخطوات بالتفصيل:

1. إنشاء ProjectModel:
   project_model = await ProjectModel.create_instance(db_client=request.app.db_client)

2. البحث عن project أو إنشاء واحد:
   project = await project_model.get_project_or_create_one(project_id=project_id)

   لو المشروع موجود في MongoDB يرجعه.
   لو مش موجود ينشئه.

3. إنشاء DataController:
   data_controller = DataController()

4. التحقق من الملف:
   is_valid, result_signal = data_controller.validate_uploaded_file(file=file)

   بيتأكد من:
   - content_type مسموح
   - size أقل من الحد الأقصى

5. لو الملف غير صالح:
   يرجع 400 ومعاه signal مثل:
   file_type_not_supported
   أو
   file_size_exceeded

6. تحديد مسار المشروع:
   ProjectController().get_project_path(project_id=project_id)

   ده ينشئ فولدر داخل:
   src/assets/files/{project_id}

7. توليد اسم ملف فريد:
   file_path, file_id = data_controller.generate_unique_filepath(...)

   بيضيف random string قبل اسم الملف.

8. حفظ الملف على الديسك:
   async with aiofiles.open(file_path, "wb") as f:
       while chunk := await file.read(app_settings.FILE_DEFAULT_CHUNK_SIZE):
           await f.write(chunk)

   هنا بيقرأ الملف على أجزاء عشان ما يحملش الملف كله في الذاكرة.

9. إنشاء AssetModel:
   asset_model = await AssetModel.create_instance(...)

10. إنشاء سجل Asset:
    Asset(
      asset_project_id=project.id,
      asset_type="file",
      asset_name=file_id,
      asset_size=os.path.getsize(file_path)
    )

11. حفظ سجل asset في MongoDB.

12. يرجع:

{
  "signal": "file_upload_success",
  "file_id": "..."
}

مهم:
file_id الراجع هنا هو MongoDB ObjectId الخاص بسجل asset، وليس اسم الملف.
لكن في process endpoint الكود يسمح بالبحث بالـ ObjectId أو باسم الملف.


Endpoint 2:
POST /api/v1/data/process/{project_id}

الدالة:

process_endpoint(request, project_id, process_request)

وظيفتها قراءة الملفات المرفوعة وتقسيمها إلى chunks ثم حفظ chunks في MongoDB.

request body مبني على ProcessRequest:

{
  "file_id": "optional",
  "chunk_size": 100,
  "overlap_size": 20,
  "do_reset": false
}

الخطوات:

1. قراءة chunk_size و overlap_size و do_reset.

2. جلب أو إنشاء project.

3. إنشاء AssetModel.

4. لو المستخدم أرسل file_id:
   - يحاول يجيبه كـ ObjectId.
   - لو فشل، يحاول يجيبه كـ asset_name.
   - لو مش موجود يرجع FILE_ID_ERROR.

5. لو المستخدم لم يرسل file_id:
   - يجيب كل assets الخاصة بالمشروع ونوعها file.

6. لو مفيش ملفات:
   يرجع NO_FILES_ERROR.

7. إنشاء ProcessController للمشروع.

8. إنشاء ChunkModel.

9. لو do_reset = true:
   يحذف chunks القديمة لهذا المشروع من MongoDB.

10. لكل ملف:
    - يقرأ محتواه باستخدام loader مناسب.
    - يقسمه إلى chunks.
    - يحول كل chunk إلى DataChunk schema.
    - يحفظ chunks في MongoDB.

11. يرجع:

{
  "signal": "processing_success",
  "inserted_chunks": number,
  "processed_files": number
}

5.4 ملف src/routes/schemes/data.py

فيه Pydantic model اسمه ProcessRequest.

class ProcessRequest(BaseModel):
    file_id: str = None
    chunk_size: Optional[int] = 100
    overlap_size: Optional[int] = 20
    do_reset: Optional[bool] = False

ده شكل body الخاص بـ:

chunk_size:
عدد الحروف في كل chunk تقريبا.

overlap_size:
عدد الحروف المشتركة بين كل chunk والتي بعدها.
الهدف منه الحفاظ على السياق.

do_reset:
لو true يمسح chunks القديمة للمشروع قبل إدخال الجديدة.

validate_uploaded_file
----------------------

يأخذ UploadFile.

يتحقق من:

1. نوع الملف:
   file.content_type in FILE_ALLOWED_TYPES

2. حجم الملف:
   file.size <= FILE_MAX_SIZE * 1048576

لو النوع غير مدعوم:
يرجع:

False, "file_type_not_supported"

الأفضل بعد setting default يعمل return.


get(group, key, vars)
---------------------

مثال:

self.template_parser.get("rag", "system_prompt")

الخطوات:

1. يبني path:
   locales/{language}/{group}.py

2. لو الملف مش موجود، يجرب default language.

3. يستورد module باستخدام __import__.

4. يجيب attribute بالاسم key.

5. ينادي:
   key_attribute.substitute(vars)

يعني template لازم يكون string.Template.

if distance_method == DistanceMethodEnums.COSINE.value:
